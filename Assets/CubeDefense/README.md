# CubeWorld 第一版网格塔防

Unity 版本：2022.3.62f3c1。原来的 `Assets/Scenes/SampleScene.unity` 保留不变。

## 打开与试玩

1. 打开 `Assets/CubeDefense/Scenes/CubeWorld_Demo.unity`，等待脚本导入，点击 Play。
2. 右侧面板：Build 建塔，Ignite 点火，Inspect 只选中查看。快捷键分别为 1、2、3。
3. Space 暂停或恢复自动生成；Spawn one wave 手动生成一波。
4. Tower fire 默认关闭，方便观察路线；勾选后炮塔攻击附近怪物。
5. 普通怪红色、远程怪紫色、范围技能怪黄色，按波次轮换。青色方块是常规攻击的友方诱饵。
6. Restart demo 重载本演示场景；退出 Play 后所有本局占用、火焰和怪物状态丢弃。

场景为 16×12。橙色预设路线 A 到 G1，包含两次 `(4,2)`；青色路线 B 到 G2，经过沼泽。墙把两组路线隔开。细线仅表示原始预设路线，不随单只怪物绕行变化。

## 地图编辑

菜单：`工具 → CubeWorld → 地图编辑器`，或选中场景的 GridMap 组件，点击“打开二维地图编辑器”。退出 Play 后编辑。

1. 从 `Assets/CubeDefense/Tiles` 选择地块笔刷，点击或拖动刷格子。
2. 选择要编辑的路线，切换“出怪口”“目标点”，点击格子。
3. 切换“追加路点”，逐次点击；同一格可以多次加入。下方列表支持坐标修改、上移、下移、删除。节点序号从 0 开始。
4. 节点不必相邻，开局会按通行规则把节点之间展开为逐格列表。要指定精确走法可逐格添加节点。
5. 切换“通行方向”，设置允许离开所选格的方向后刷格。East 是 +X，North 是网格 +Y（世界 +Z）。默认 All 双向；单向通行由各格出边共同决定。
6. Ctrl+Z 撤销。点“验证路线”检查是否能经过全部节点；点“保存场景”或 Ctrl+S 保存，再重新打开场景验证。
7. 新增区域默认没有地块配置，需要刷地块；缩小地图后检查是否有越界的出怪口、目标和路点。

地块配置：Ground 地面、Wall 墙、ShallowWater 浅水、Swamp 沼泽、Grass 可燃草。可以修改颜色、可选外观预制体、通行/建造规则、速度倍率、燃烧时长和伤害。不同类型不依赖硬编码地块枚举。

## 同一演示场景中的验收步骤

1. 绕行与重复节点：重启，保持 Tower fire 关闭。趁 A 路线怪物还在前段时，在 `(6,2)` 建塔。它会修补后续两次受阻经过，继续走剩余绕圈并到 G1。右侧 A 的 repairs 增加；B 的 repairs 保持 0，继续去 G2。建造不能覆盖怪物当前占据或即将抵达的近邻格，若提示占用，等怪物走开。
2. 出怪口保护：下方通道在 x=3 列依次建 `(3,8)`、`(3,9)`、`(3,10)`，填满整列的最后一座应被拒绝，因为会封死 B 的出怪口。开始前暂停生成，避免怪物占格影响操作。
3. 被困后破障：重启后立即点 Trap demo。它关闭自动生成和塔开火，在单向格 `(4,5)` 放置远程怪，再在唯一出口 `(5,5)` 建塔。两个出怪口仍可达各自目标；该怪停下攻击塔，塔生命归零后继续前往 G1。每次演示需等待原塔摧毁或重启。
4. 障碍伤害限制：上述塔存在时点 Probe。它直接向障碍提交普通、范围及无攻击者的伪造破障伤害，结果应显示 PASS。此时真实怪物自己的破障仍会正常扣血，所以关注 Probe 的 PASS 及瞬时校验，不要把持续破障扣血误判为范围伤害。
5. 常规远程/范围行为：重启后等待紫色、黄色怪走近 `(6,4)` 的青色诱饵，观察 Normal hits / area hits 增长。在其附近放塔，普通技能不会选塔，也不能用范围伤害伤塔；只有实际受困才进入公共破障行为。
6. 地块规则：浅水 `(9..11,4)` 不可进入或建造；B 经过 `(7..9,9)` 沼泽时减速。切换 Ignite 后点 `(10,2)`，只有该格变成火焰颜色，其他引用相同 Grass 资产的格子不燃烧，8 秒后恢复。
7. 道路恢复：破障后，新生成怪使用已畅通的原预设路线。已在绕行的怪不会立即掉头换路，而是按自身临时列表到接点后继续旧后缀。

1. 使用本机 Unity 2022.3 的 Roslyn 编译器及 Unity 程序集编译全部 Runtime/Editor 脚本，无编译错误。这属于引擎外编译检查。
2. 直接编译真实 GridMap、PathService、Monster、Obstacle 等源码，用最小 Unity API 替身运行 22 项逻辑检查，通过。覆盖重复路点、最长合法前缀、倒查接点、后续重复堵点、共享搜索、单向边、个体受困、非法伤害拒绝、远程怪公共破障、破障后到达目标、无关怪不修补、道路开放时保留绕行等。
3. 另以独立正向搜索对照反向搜索，2,160 次随机有向图可达性检查通过。
4. 读取交付场景文件检查：192 个按行排列的格子、脚本和地块 GUID 引用、场景内部对象引用、两条通往不同目标的路线、重复节点、单向受困格均通过检查。
5. 检查输出在 `Logs/CubeDefense-compile-check.txt`、`Logs/CubeDefense-standalone-tests.txt`、`Logs/CubeDefense-scene-check.txt`。

## 代码模块笔记

1. TileDefinition：地块配置资产；存颜色、外观预制体、通行和燃烧参数。
2. GridMap：场景中的地图数据。Resize 调整尺寸；ResetState 创建本局状态；Open 判断格子可站立；Edge 统一判断有向边是否合法。
3. RouteDefinition：出怪口、目标和有序节点。Expand 展开逐格路线，保留重复经过。
4. PathService：一次地图变化的寻路缓存。To 获取共用反向搜索场；RequiredConnected 校验出怪口；Valid 检查剩余路线；Repair 拼接旧前缀、绕行和旧后缀。
5. ReverseField：以某一格为目的的反向广度优先搜索。Reaches 判断可达；Path 从任意可达起点还原路径。
6. Monster：每只怪物独立保存 Plan 和 NextIndex。MapChanged 处理剩余路线；IsActuallyBlockedBy 重新验证实际堵点；RegularAttack 是子类常规技能入口。
7. RangedMonster / AreaMonster：只实现常规攻击，共用 Monster 的移动与破障。CombatDummy 是演示用普通受击单位。
8. Obstacle：炮塔与障碍。ReceiveDamage 是唯一障碍扣血入口，拒绝普通、范围和冒充破障的伤害。
9. DefenseGame：初始化、建塔、生成、点火与演示按钮。TryBuild 先试算后占用；NotifyChange 为同次变化共享寻路缓存；TrapDemo 复现受困；DamageProbe 验证伤害入口。
10. MapEditorWindow：二维编辑窗口；Undo.RecordObject 记录修改前状态；EditorSceneManager.SaveScene 保存场景；DemoBuilder 生成和验收示例。

第一版以规则可验证为主：方块使用运行时生成的简单材质，技能是数值结算，没有动画和特效；仅有地面怪通行类型，没有经济、胜负或波次关卡结算系统。
